# Trajectory Tracking for a Multicopter under a Quaternion Representation

# 1. Abstract

This project presents the design, implementation, and simulation of a nonlinear trajectory-tracking controller for a quadrotor UAV using differential flatness and quaternion-based attitude control.

The quadrotor is a nonlinear and underactuated aerial vehicle in which translational and rotational dynamics are strongly coupled. To address this problem, a hierarchical control architecture is developed. The outer-loop position controller tracks a desired three-dimensional trajectory and generates the required translational acceleration. A differential-flatness-based mapping is then used to determine the desired attitude and thrust. The inner-loop attitude controller uses quaternion representation and nonlinear computed-torque control to generate the required control torque.

The complete closed-loop system is implemented in MATLAB/Simulink. The model includes reference trajectory generation, position control, differential-flatness mapping, quaternion attitude control, translational dynamics, rotational dynamics, quaternion kinematics, feedback, and data logging.

A smooth quintic trajectory is generated over a 10-second simulation interval. The performance of the controller is evaluated using position tracking error, quaternion tracking error, thrust, control torque, and angular velocity.

The obtained position RMSE values are:

| Axis | RMSE |
|---|---:|
| X | 0.006659 m |
| Y | 0.004419 m |
| Z | 0.000041 m |

The quaternion tracking errors are:

| Component | RMSE |
|---|---:|
| $q_1$ | $1.6557 \times 10^{-4}$ |
| $q_2$ | $2.4949 \times 10^{-4}$ |
| $q_3$ | $1.2512 \times 10^{-19}$ |

The project also includes a MATLAB-based 3-D quadrotor animation that visualizes the actual vehicle position and attitude using the simulated quaternion state. MuJoCo is included as an additional physics-based simulation and visualization environment.

# 2. Introduction

Quadrotors are one of the most widely studied classes of unmanned aerial vehicles because of their mechanical simplicity, maneuverability, and ability to perform vertical take-off and landing.

However, controlling a quadrotor accurately is challenging because the system is nonlinear, underactuated, and dynamically coupled. Translational motion depends on vehicle orientation, while the orientation is controlled through body torques generated by the rotors.

For accurate trajectory tracking, the controller must therefore coordinate both translational and rotational motion.

This project investigates a hierarchical nonlinear control architecture based on differential flatness and quaternion-based attitude control.

The architecture separates the control problem into two main layers:

1. **Outer-loop position control**
2. **Inner-loop attitude control**

The position controller tracks the desired position and velocity and generates a desired translational acceleration. Differential flatness is then used to map this desired translational behavior to a desired attitude and thrust.

The attitude controller receives the desired quaternion and actual vehicle attitude and generates the required control torque.

The complete system is simulated in MATLAB/Simulink, while MuJoCo is considered as an additional physics-based validation and visualization environment.

# 3. Problem Statement

The objective is to design a closed-loop controller capable of making a quadrotor follow a smooth three-dimensional reference trajectory while maintaining the required attitude.

The controller should:

- track the desired $x, y, z$ position,
- minimize position tracking error,
- generate appropriate thrust,
- generate the desired vehicle attitude,
- track the desired quaternion,
- generate stabilizing control torques,
- maintain bounded angular velocity,
- preserve quaternion normalization,
- and demonstrate the complete behavior through simulation and visualization.

# 6. Mathematical Model

## 6.1 Coordinate Frames

Two coordinate frames are considered:

### Inertial frame

\[
\mathcal{F}_I = \{X_I,Y_I,Z_I\}
\]

This frame represents the fixed world/reference coordinate system.

### Body frame

\[
\mathcal{F}_B = \{X_B,Y_B,Z_B\}
\]

This frame is attached to the quadrotor body.

---

# 7. Translational Dynamics

Let the position of the quadrotor be

\[
\xi =
\begin{bmatrix}
x\\
y\\
z
\end{bmatrix}.
\]

The translational dynamics can be represented as

\[
m\ddot{\xi}
=
mg e_3 + R(q)e_3T
\]

where:

- \(m\) = quadrotor mass,
- \(g\) = gravitational acceleration,
- \(T\) = total thrust,
- \(R(q)\) = rotation matrix corresponding to quaternion \(q\),
- \(e_3=[0,0,1]^T\).

Depending on the adopted thrust and coordinate sign convention, the gravity/thrust signs are determined consistently throughout the implementation.

---

# 8. Rotational Dynamics

The rotational dynamics are modeled using Euler's rigid-body equation:

\[
J\dot{\omega}
+
\omega\times(J\omega)
=
\tau
\]

where:

- \(J\) = inertia matrix,
- \(\omega=[\omega_x,\omega_y,\omega_z]^T\) = body angular velocity,
- \(\tau=[\tau_x,\tau_y,\tau_z]^T\) = control torque.

Therefore,

\[
\dot{\omega}
=
J^{-1}
\left[
\tau-\omega\times(J\omega)
\right].
\]

This equation is implemented inside the `RotDynamics` subsystem.

---

# 9. Quaternion Representation

The quaternion is represented as

\[
q=
\begin{bmatrix}
q_0\\
q_1\\
q_2\\
q_3
\end{bmatrix}.
\]

The unit-quaternion constraint is

\[
\|q\|=1.
\]

The quaternion kinematic equation is expressed as

\[
\dot q
=
\frac{1}{2}q\otimes
\begin{bmatrix}
0\\
\omega
\end{bmatrix}
\]

where \(\otimes\) denotes quaternion multiplication.

The quaternion is normalized during simulation to prevent numerical drift:

\[
q
\leftarrow
\frac{q}{\|q\|}.
\]

---

# 10. Quaternion Multiplication

For two quaternions

\[
q=(q_0,\mathbf q)
\]

and

\[
r=(r_0,\mathbf r),
\]

their product is

\[
q\otimes r
=
\left(
q_0r_0-\mathbf q^T\mathbf r,
\;
q_0\mathbf r+r_0\mathbf q+\mathbf q\times\mathbf r
\right).
\]

The quaternion conjugate is

\[
q^*
=
\begin{bmatrix}
q_0\\
-q_1\\
-q_2\\
-q_3
\end{bmatrix}.
\]

---

# 11. Differential Flatness

Differential flatness allows a nonlinear system to be parameterized using a set of flat outputs.

For the quadrotor formulation used in the project, the flat-output concept is associated with translational position and an attitude-related component:

\[
z_f=
\begin{bmatrix}
x\\
y\\
z\\
q_3
\end{bmatrix}.
\]

The flatness mapping allows the system states and required inputs to be reconstructed from the flat outputs and their derivatives.

The project therefore uses the following conceptual transformation:

\[
\boxed{
(x,y,z,q_3)
\rightarrow
\text{desired state and input quantities}
}
\]

The `FlatnessMap` subsystem performs this transformation in the Simulink implementation.

---

# 12. Reference Trajectory Generation

A smooth quintic trajectory is used to move the quadrotor from the initial point

\[
p_0=
\begin{bmatrix}
1.8\\
2.27\\
0.6
\end{bmatrix}
\]

to the destination

\[
p_f=
\begin{bmatrix}
2.9\\
3.0\\
1.2
\end{bmatrix}.
\]

The trajectory duration is

\[
T=10\;s.
\]

The normalized time is

\[
\tau=
\frac{t-t_0}{T}.
\]

The quintic interpolation function is

\[
s(\tau)
=
10\tau^3
-
15\tau^4
+
6\tau^5.
\]

Therefore,

\[
\xi_r(t)
=
p_0+
(p_f-p_0)s(\tau).
\]

The velocity reference is

\[
\dot{\xi}_r(t)
=
(p_f-p_0)\dot{s}(\tau)
\]

where

\[
\dot{s}
=
\frac{
30\tau^2
-
60\tau^3
+
30\tau^4
}{T}.
\]

The acceleration reference is

\[
\ddot{\xi}_r(t)
=
(p_f-p_0)\ddot{s}(\tau)
\]

where

\[
\ddot{s}
=
\frac{
60\tau
-
180\tau^2
+
120\tau^3
}{T^2}.
\]

The boundary conditions are

\[
s(0)=0,\qquad s(1)=1
\]

and

\[
\dot{s}(0)=\dot{s}(1)=0
\]

and

\[
\ddot{s}(0)=\ddot{s}(1)=0.
\]

Therefore, the vehicle starts and ends the trajectory smoothly.

---

# 13. Position Controller

The position error is defined as

\[
e_\xi
=
\xi_r-\xi.
\]

The velocity error is

\[
e_{\dot{\xi}}
=
\dot{\xi}_r-\dot{\xi}.
\]

A PID-type position control structure is implemented.

The proportional term is

\[
u_P=K_{p,\xi}e_\xi.
\]

The integral term is

\[
u_I=
K_{i,\xi}
\int e_\xi\,dt.
\]

The derivative term is

\[
u_D=
K_{d,\xi}e_{\dot{\xi}}.
\]

The desired translational acceleration is then constructed from the reference acceleration and feedback terms:

\[
\boxed{
\ddot{\xi}^{*}
=
\ddot{\xi}_r
+
K_{p,\xi}e_\xi
+
K_{i,\xi}\int e_\xi dt
+
K_{d,\xi}e_{\dot{\xi}}
}
\]

with the exact sign convention implemented consistently in the Simulink model.

---

# 14. Flatness Mapping

The desired translational acceleration generated by the position controller is passed to the flatness mapping block.

The purpose of this block is to transform the desired translational behavior into:

\[
q_r
\]

and

\[
T.
\]

Therefore:

\[
\boxed{
\ddot{\xi}^{*}
\rightarrow
(q_r,T)
}
\]

The desired quaternion is then provided to the attitude controller.

The thrust command is provided directly to the plant.

---

# 15. Attitude Control

The attitude controller receives:

- desired quaternion \(q_r\),
- actual quaternion \(q\),
- desired quaternion derivative,
- actual angular velocity \(\omega\),
- inertia matrix \(J\).

The quaternion tracking error can be represented using

\[
q_e=q_r\otimes q^*.
\]

The vector part of the error quaternion is used as the attitude error:

\[
e_q=
\operatorname{vec}(q_e).
\]

The angular velocity tracking error is

\[
e_\omega
=
\omega_r-\omega.
\]

For the implemented simulation, the desired angular-rate reference is taken according to the controller structure used in the model.

The computed-torque control law has the general form

\[
\boxed{
\tau
=
J\dot{\omega}^{*}
+
\omega\times J\omega
-
K_{p,q}e_q
-
K_{d,q}e_\omega
-
K_{i,q}\int e_q\,dt
}
\]

with the implemented sign and reference conventions defined by the Simulink controller.

The gyroscopic compensation term

\[
\omega\times J\omega
\]

compensates for the nonlinear rotational coupling.
